# SoundCloud API Endpoint Reference

Quick reference for every SoundCloud endpoint used in this codebase — what credential each one requires and where it's called.

---

## Credential Types

| Name        | How It's Obtained                                                                         | Env Var                           | Notes                                                                        |
| ----------- | ----------------------------------------------------------------------------------------- | --------------------------------- | ---------------------------------------------------------------------------- |
| `CLIENT_ID` | Auto-scraped from `soundcloud.com` HTML (`window.__sc_hydration`)                         | `SOUNDCLOUD_CLIENT_ID` (fallback) | Cached 14 days via `unstable_cache`. Generated by `auth/route.ts`.           |
| `GUEST_KEY` | Extracted from `track_authorization` on a public playlist (auto-scraped with `CLIENT_ID`) | —                                 | OAuth token; valid for ~14 days. Also auto-generated in `auth/route.ts`.     |
| `API_KEY`   | **Manual** — must be obtained from the SoundCloud developer portal                        | `SOUNDCLOUD_API_KEY`              | Full OAuth token. Only needed as a fallback when `GUEST_KEY` is unavailable. |

**Both `CLIENT_ID` and `GUEST_KEY` are auto-generated** — you never need to set them manually. The only credential you may need to set manually is `SOUNDCLOUD_API_KEY`.

Credentials are fetched via `scAuth()` from `src/lib/config.ts`, which calls `getSoundCloudCredentials()` from `auth/route.ts`.

---

## Endpoints: CLIENT_ID Only

These endpoints work with just the scraped `CLIENT_ID`. **No manual API key required.**

| Endpoint                              | Description                               | Route File(s)                                                 |
| ------------------------------------- | ----------------------------------------- | ------------------------------------------------------------- |
| `GET /search?q=…&client_id=…`         | Full search (tracks, people, playlists)   | `route.ts`, `search/route.ts`                                 |
| `GET /search/queries?q=…&client_id=…` | Search autocomplete suggestions           | `search/route.ts`                                             |
| `GET /mixed-selections?client_id=…`   | Home page featured sections               | `home/section/route.ts`                                       |
| `GET /tracks/{id}?client_id=…`        | Single track info                         | `[id]/route.ts`, `track/info/[id]/route.ts`                   |
| `GET /tracks?ids=…&client_id=…`       | Bulk track info (up to 50 IDs)            | `[id]/route.ts`, `playlist/[id]/route.ts`                     |
| `GET /playlists/{id}?client_id=…`     | Playlist / album details + track list     | `[id]/route.ts`, `playlist/[id]/route.ts`                     |
| `GET /users/{id}?client_id=…`         | User / artist profile                     | `[id]/route.ts`, `artist/info/[id]/route.ts`, `user/route.ts` |
| `GET /users/{id}/tracks?client_id=…`  | User's uploaded tracks                    | `[id]/route.ts`, `artist/recent/[id]/route.ts`                |
| `GET /users/{id}/likes?client_id=…`   | User's liked tracks                       | `user/route.ts`                                               |
| `GET /stream/users/{id}?client_id=…`  | User's recent activity / stream           | `[id]/route.ts`                                               |
| `GET /resolve?url=…&client_id=…`      | Resolve a permalink to an entity (API v2) | `music/route.ts`, `resolve/route.ts`                          |
| `GET /resolve.json?url=…&client_id=…` | Resolve a permalink to an entity (API v1) | `resolve/route.ts`                                            |
| `GET <hls_url>?client_id=…`           | Fetch HLS M3U8 stream URL from CDN        | `music/route.ts`                                              |

## Endpoints: OAuth Token Required

These endpoints require an `Authorization: OAuth <token>` header. The `GUEST_KEY` (auto-generated) satisfies this in practice. The `SOUNDCLOUD_API_KEY` env var is only used as a fallback.

| Endpoint                    | Description                        | Auth Used                                                   | Route File(s)                    |
| --------------------------- | ---------------------------------- | ----------------------------------------------------------- | -------------------------------- |
| `GET /users/{id}/spotlight` | Artist's featured/spotlight tracks | `Authorization: OAuth ${GUEST_KEY \|\| SOUNDCLOUD_API_KEY}` | `artist/spotlight/[id]/route.ts` |

### Notes on Spotlight

- `artist/spotlight/[id]/route.ts` — **correctly** sends `Authorization: OAuth ${GUEST_KEY}` (no `client_id` param).
- `soundcloud/[id]/route.ts` (when `?type=artist&include=spotlight`) — calls the same URL **with `client_id` only** (no Authorization header). This may silently fail or return limited data for some accounts.

## Endpoints: No Auth Needed (HTML Scraping)

| Operation                           | Description                                                        | Route File             |
| ----------------------------------- | ------------------------------------------------------------------ | ---------------------- |
| `GET https://soundcloud.com` (HTML) | Scrape `window.__sc_hydration` to extract `client_id`              | `auth/route.ts`        |
| `GET <permalink URL>` (HTML)        | Scrape `<meta property="al:ios:url">` to extract track/playlist ID | `getid/[url]/route.ts` |
| `GET <user profile URL>` (HTML)     | Scrape `<meta property="twitter:app:url:googleplay">` for user ID  | `user/route.ts`        |

---

## Summary

```
CLIENT_ID (auto-generated) ─── covers ~95% of all endpoints
GUEST_KEY (auto-generated) ─── required for /spotlight only
API_KEY   (manual)         ─── fallback for /spotlight if GUEST_KEY is missing
```

You should **never need to manually set `SOUNDCLOUD_API_KEY`** in normal operation because `GUEST_KEY` is auto-generated and covers the spotlight endpoint. `SOUNDCLOUD_API_KEY` is only a safety net.

---

## Known Issue

In `soundcloud/[id]/route.ts`, the bulk tracks hydration uses `apiKey` (which is `GUEST_KEY || SOUNDCLOUD_API_KEY`) as the `client_id` query parameter:

```ts
// BUG: should be &client_id=${CLIENT_ID}, not &client_id=${apiKey}
`https://api-v2.soundcloud.com/tracks?ids=…&client_id=${apiKey}`;
```

This works by coincidence when `CLIENT_ID === apiKey`, but should use `CLIENT_ID` explicitly.
